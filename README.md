# About This Project

This project was created as a professional portfolio to showcase my work to recruiters, engineering leaders, companies, and QA professionals who want to learn, evaluate, or explore modern ways of structuring automated tests.

The project is based on the Petstore API, a public and well-known REST API provided by Swagger, available at:
[Petstore API](https://petstore.swagger.io/#/)

Using this API, I built a complete API test automation framework that demonstrates:

- Real-world API testing scenarios
- Clean test architecture and organization
- Reusable service and request layers
- Positive and negative test coverage
- Validation of responses, status codes, and business rules
- Integration-ready structure for CI/CD pipelines

The goal is not just to test the Petstore API itself, but to demonstrate how a professional QA/SDET would design, structure, and maintain an automated testing project that could be used in a real company.

This repository serves as:

- A technical portfolio
- A reference architecture for API test automation
- A learning resource for QA engineers, SDETs, and teams looking to improve their test automation practices

# QA - Automated Testing Project and Its Structure with Cypress

This repository contains automated tests for the Petstore API project located within the 'api' folder, which is executed in different environments (Quality and Development). The tests are implemented using Cypress, an open-source web application testing automation tool [official documentation](https://docs.cypress.io/guides/overview/why-cypress). 

## Prerequisites

Before you begin, make sure that your machine has **Node.js** and **Cypress** installed so that you can run the tests correctly.

For more details on how to install and configure these components, refer to the complete document that provides a detailed step-by-step guide for the entire process. You can access it through this link [Installation, Configuration, and Test Execution Guide with Cypress](Under construction).

## Installation

1. Clone this repository to your development environment:

```shell
git clone git@github.com:massayoshi-campos/cypress-rest-api-testing.git
```

2. Navigate to the project directory in the 'api' folder:

```shell
cd 'Your repository\cypress-rest-api-testing\api'
```

3. Install project dependencies using npm:

```shell
npm install
```

The project structure consists of the following elements:

- **cypress**: This is the main folder containing all files related to automation tests using the Cypress framework.
- **config**: The "config" folder holds configuration files for different environments. In this case, there are two files, "dev.json" and "qa.json," which contain environment-specific settings for development and QA (Quality Assurance), respectively.
- **e2e**: The "e2e" folder contains end-to-end tests that will be executed in the project.
- **fixtures**: The "fixtures" folder contains data files that can be used in tests.
- **plugins**: The "plugins" folder may contain custom extension modules or additional configurations for Cypress.
- **services**: This folder is dedicated to storing modules or services that perform auxiliary functions, integrate with APIs, and handle other operations related to automation testing.
- **support**: The "support" folder is used to store support files, such as custom commands ("commands.js") or specific configurations for end-to-end tests ("e2e.js").
- **mochawesome-report**: This folder contains the results of reports generated by Mochawesome Report. It may include visual reports or information about test execution.
- **node-modules**: This folder is automatically generated by the package manager (npm) and contains all project dependencies.
- **Cypress.config.js**: This is the primary configuration file for Cypress in the project. It may contain global settings.
- **package-lock.json**: This file is used to lock the exact versions of project dependencies, ensuring consistency across different development environments.
- **package.json**: The "package.json" file contains project information, such as metadata, custom scripts, and project dependencies.

# Mochawesome Documentation

This project uses Mochawesome to generate visually appealing test reports. Below are the available scripts for creating and merging the reports.

## Scripts

### cypress:merge-reports-json

The **`cypress:merge-reports-json`** script is responsible for merging the JSON files of the reports generated by Mochawesome.

To execute the script, use the following command:

```shell
npm run cypress:merge-reports-json
```

### cypress:generate-report-html

The **`cypress:generate-report-html`** script generates the final HTML report based on the merged JSON file.

To execute the script, use the following command:

```shell
npm run cypress:generate-report-html
```

### cypress:merge-report-html

The **`cypress:merge-report-html`** script merges the HTML reports generated by Mochawesome.

To execute the script, use the following command:

```shell
npm run cypress:merge-report-html
```

### report:cleanup

The **`report:cleanup`** script is used to delete files with a specific pattern **"mochawesome\_\*.json"**. It will delete all files that start with **"mochawesome\_"** and have the extension **".json"**

To execute the script, use the following command:

```shell
npm run report:cleanup
```

### report:cleanup-xml

The **`report:cleanup-xml`** script is used to delete files with a specific pattern **"junit-report-*.xml"** within the **"mochawesome-report"** directory. It will delete all files that start with **"junit-report-"** and have the extension **".xml"**.

To execute the script, use the following command:

```shell
npm run report:cleanup-xml
```

### Execution Sequence

It's important to run the scripts in the following order:

1. cypress:merge-reports-json
2. cypress:generate-report-html
3. cypress:merge-report-html

**Make sure you have the Mochawesome dependencies installed before running these scripts.**

| **Script**                         | **Description**                 | **Execution**  |
| ---------------------------------- | ------------------------------- | -------------- |
| cypress:merge-reports-json         | Merge JSON report files         | Pipeline/Local |
| cypress:generate-report-html       | Generate HTML report            | Pipeline       |
| cypress:merge-report-html          | Merge HTML report files         | Pipeline       |
| cypress:generate-report-html-local | Generate HTML report (local)    | Local tests    |
| cypress:merge-report-html-local    | Merge HTML report files (local) | Local tests    |

This table presents a division of the scripts into two categories: Pipeline and Local.

On the other hand, the scripts marked with **"Local"** should be executed for local tests. They also merge JSON report files, generate HTML reports, and merge HTML report files, but for the local environment.

Make sure to run the scripts corresponding to the appropriate category, depending on the context you are working in: either in the CI pipeline or for local tests.

# Test Execution Documentation (GitHub Actions Pipeline)

The GitHub Actions CI/CD pipeline is configured to run all tests in a single job, responsible for validating the application by executing all test specs.

In this model, one main job runs all test suites sequentially, such as:

- `test-api-qa-petstore-pet`

It makes the pipeline easier to understand, maintain, and troubleshoot.

This job is responsible for:

- Installing dependencies.
- Setting up the test environment.
- Running all defined test specs.
- Generating execution reports.

By running all tests in one place, we ensure that all system features and components are validated in a consistent and reliable way. It also makes it much easier to analyze failures, reproduce issues, and track overall quality.

Using a single job also avoids synchronization issues between stages, keeping the pipeline simpler, more predictable, and more stable.
